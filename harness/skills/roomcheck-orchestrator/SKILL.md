# 룸체크 개발 오케스트레이터

## 팀 구성
| 에이전트 | 역할 | 입력 ← 출처 | 출력 → 대상 |
|---------|------|------------|------------|
| builder | 코드 구현 | 사용자 요구사항 ← 오케스트레이터 | 변경 요약+테스트 포인트 → tester, auditor |
| tester  | Playwright 검증 | 테스트 포인트 ← builder | PASS/FAIL → 오케스트레이터 |
| auditor | 규칙 검수 | 변경 요약 ← builder | 통과/반려 → 오케스트레이터 |

## 실행 순서
1. 사용자 요구사항을 정리해 **builder**에게 전달 (관련 규칙 메모 포함).
2. builder 완료 후 **tester**와 **auditor**를 병렬 실행 (둘 다 builder 출력만 필요).
3. 둘 다 통과 → 4단계. 하나라도 실패/반려 → 실패 상세를 builder에게 전달해 재수정. **반려 루프 최대 2회**, 초과 시 사용자에게 상황 보고 후 지시 대기.
4. 배포: roomcheck-deploy 스킬 절차 수행 (오케스트레이터가 직접 — 서브 에이전트에 위임하지 않음. SendUserFile→device_commit_files 연계가 메인 세션에서만 안정적).
5. 사용자에게 한국어로 결과 요약 보고 (변경 내용, 테스트 결과, 새로고침 안내).

## 에러 핸들링
- 에이전트 출력이 형식과 다르면: 형식을 다시 제시하고 1회 재요청.
- tester FAIL: 실패 상세를 builder에 반려 (최대 2회).
- auditor 반려: 위반 항목을 builder에 반려 (최대 2회).
- 기기 연결(device bridge) 끊김: ToolSearch로 도구 재로드 후 재시도, 그래도 실패하면 파일 첨부로 대체하고 사용자에게 알림.

## 완료 기준
tester PASS + auditor 통과 + 맥 폴더 저장 성공 + 프로젝트 문서(claude/site/*) 갱신 완료.

## 간단 작업 예외
한 줄 텍스트 수정, 색상 하나 변경 같은 사소한 작업은 팀을 띄우지 않고 메인 세션이 직접 수정 → node --check → 간단 확인 → 배포해도 된다. 단 i18n 3언어 동기화와 배포 절차는 동일하게 지킨다.
